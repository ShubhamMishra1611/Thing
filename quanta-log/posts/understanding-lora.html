Understanding LoRA

Apr 10 2024 8 min read Shubham Mishra

The domain of AI is expanding, and each sector is trying to leverage the power of AI in its system. We are witnessing fast-paced development and introduction of new LLMs, frameworks to handle them, finetuning them, and integrating them into existing systems, which is currently booming.

One of the promising methodologies that helps a lot nowadays is finetuning. Finetuning refers to training a pre-trained model (mainly those large models) on a new dataset specific to a task. This helps in adapting the model and making it efficient in that task.

Today, we will explore a fantastic technique called LoRA, from what this is to how to do it.

LoRA: Low-Rank Adaptation of Large Language Model. We will start by brushing some concepts of linear algebra.

Rank of a Matrix: The maximum number of linearly independent columns (or rows) of a matrix. For a full rank matrix, the rank equals the number of rows (or columns) in the matrix. A full-rank matrix is a matrix where all its rows and columns are linearly independent. So basically, no row or column in the matrix can be expressed as a linear combination of the other rows or columns.

We can get the rank of a matrix using NumPy. Here are examples:

import numpy as np

matrix = np.array([[1, 0, 0],
                   [0, 1, 0],
                   [0, 0, 1]])

# Check the rank of the matrix
rank = np.linalg.matrix_rank(matrix)
print("Rank of the matrix:", rank)

# Check the dimension of the matrix
dimension = matrix.shape[0]

Low-Rank Approximation of Matrix

Low-rank approximation is the main idea that LoRA works upon. The idea is that we have a matrix A with rank r, then it can be decomposed into B and C such that A = BC, where A = m × n, B = m × r, and C = r × n.

In mathematics, low-rank approximation is a minimization problem to bring the original matrix and approximating matrix closer (the closeness is measured by a given cost function), and we are subjected to the constraint that the approximating matrix has reduced rank r.

It is like summarizing an extensively detailed report into a few key points, such that the summary is still very close to the original report.

On Wikipedia, this problem is structured as follows:

The solution is called the matrix approximation lemma or Eckart–Young–Mirsky theorem. The solution incorporates the logic of SVD.

Let the singular value decomposition of D be denoted as 𝐃, where Σ = diag(σ₁, …, σₘ) is the m × n rectangular diagonal matrix with the singular values σ₁ ≥ … ≥ σₘ. For a given r ∈ {1, …, m-1}, partition U, Σ, and V as follows:

where U₁ is m × r, Σ₁ is r × r, and V₁ is r × n. Then, the rank-r matrix, obtained from the truncated singular value decomposition.

This minimizer exists if and only if σᵣ₊₁ ≠ σᵣ.

The code corresponding to the above would look like this

# Let us say there are two matrix W and b.
y = W@ x + b

# Perform SVD on W #
U, S, V = torch.svd(W)

# For rank-r factorization, keep only the first r singular values (and corresponding columns of U and V)
U_r = U[:, :r]
S_r = torch.diag(S[:r])
V_r = V[:, :r].t()  # Transpose V_r to get the right dimensions

# Compute C = U_r * S_r and R = V_r
C = U_r@S_r
R = V_r
# -------------------------------------------

# Compute y' = CRx + b
y_prime = (C@R)@x+ b

Incorporating LoRA

In a given model, let's say we have a matrix represented by W₀ (with dimension (𝑑×𝑘)); when we fine-tune this model, the update to this weight matrix, denoted as Δ𝑊 is constrained to BA, where 𝐵=(𝑑×𝑟) and 𝐴=(𝑟×𝑘) and 𝑟 ≪ min(𝑑, 𝑘).

In simpler terms, during fine-tuning, instead of directly updating the weight matrix by Δ𝑊, we update it by a new matrix BA, where 𝐵 and 𝐴 are smaller matrices, ensuring that the update is constrained to a smaller subset of the original weight matrix.

During training, original weights or 𝑊ₒ are frozen, while A and B are trainable. So the end equation looks like this: h = W₀x + ΔWx = W₀x + BAx

In the LoRA paper, they weigh the Delta matrix with an α parameter. The variable α helps in defining how much the effect ΔW will have.

Now, let's move to the implementation part of LoRA.

We do have PEFT from HuggingFace, and we can use it directly, but let's just write it from scratch because why not?

First, let us define a simple FFN:

import torch
class FFN(torch.nn.Module):
  def __init__(self, in_dim, out_dim, hid_dim = 32):
    super().__init__()
    self.l1 = torch.nn.Linear(
        in_dim, hid_dim
    )
    self.l2 = torch.nn.Linear(
        hid_dim, out_dim
    )
    self.relu_l = torch.nn.ReLU()

  def forward(self, x):
    x = self.l1(x)
    x = self.l2(x)
    x = self.relu_l(x)
    return x

model = FFN(256, 10)

Our model looks like this:

FFN(
  (l1): Linear(in_features=256, out_features=32, bias=True)
  (l2): Linear(in_features=32, out_features=10, bias=True)
  (relu_l): ReLU()
)

Let's define a new layer now:

class LoRA_layer(torch.nn.Module):
  def __init__(self, in_dim, out_dim, rank):
    super().__init__()
    std_dev = 1/torch.sqrt(torch.tensor(rank).float())
    self.A = torch.nn.Parameter(
        torch.randn(in_dim, rank)*std_dev
      )
    self.B = torch.nn.Parameter(
        torch.zeros(rank, out_dim)
      )

  def forward(self, x):
    x = x @ self.A @ self.B
    return x

Pay attention to the fact that A matrix is scaled down by std_dev, as discussed in the original paper.

class LoRAonLinear(torch.nn.Module):
    def __init__(self, linear, rank, alpha):
        super().__init__()
        self.linear = linear
        self.lora = LoRA_layer(
            linear.in_features, linear.out_features, rank
        )
        self.alpha = alpha

    def forward(self, x):
        return self.linear(x) + self.alpha * self.lora(x)

Now let's assign LoRA on linear,

from functools import partial
assigner = partial(LoRAonLinear, rank=8, alpha=0.5)
model_layer = [layer for layer in model.modules() if isinstance(layer, torch.nn.Linear)]

for layer in model_layer:
    layer = assigner(layer)
    print(layer)
LoRAonLinear(
  (linear): Linear(in_features=256, out_features=32, bias=True)
  (lora): LoRA_layer()
)
LoRAonLinear(
  (linear): Linear(in_features=32, out_features=10, bias=True)
  (lora): LoRA_layer()
)

With this, we can fine-tune our model for a new task.

NOTE: One thing mentioned in the paper is that it is not anticipated that small r will work on every task. So if the downstream task were in a different language than one used for pre-training, r = dₘ (dimension of the model) will certainly outperform LoRA with a small r, which means retraining the entire model will perform better.

Conclusion

We saw that LoRA, indeed, is a very versatile technique, where you can efficiently train your model for a specific task; we also easily change from one particular task to another just by simply replacing AB with a new task CD, with little memory overhead.

The exploration of LoRA for fine-tuning Large Language Models opens up new avenues in the field of ML and NLP. As we continue to push the boundaries of what's possible with LLMs, techniques like LoRA will undoubtedly play a significant role in shaping the future of this exciting field.
