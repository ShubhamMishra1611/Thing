Speculative Decoding: LLM be like You start bro, I've got your back

Jan 9 2025 6 min read Shubham Mishra

When AI generates text, it determines the next word based on patterns it has learned from vast amounts of data. This process is known as decoding. One very 'clean' method of decoding is Speculative Decoding.

Decoding

So decoding is selecting the following word (or token) in a sentence. But here's the tricky part: balancing speed, quality, and creativity.

When writing a story (I mean when an LLM is generating text), you could choose the most likely word every time — that's Greedy Decoding, straightforward, with no extra effort, and deterministic. Or, you might select from a range of possible words, introducing a bit of randomness for more varied outcomes — this is Nucleus Sampling. Both are familiar techniques that guide how text is generated, but they each have their limitations in terms of balance between predictability and creativity. Speculative Decoding builds on these methods. Instead, it takes things to another level, using more LLMs to enhance speed and coherence without sacrificing flexibility.

WHHAAAAAT?

Speculative Decoding: A Tag Team of Models

Think of Speculative Decoding like teamwork. You've got:

  • The Draft Model: A quick, smaller AI that proposes a few word options, like a junior writer brainstorming ideas.
  • The Target Model: A larger, more accurate AI that reviews and approves (or rejects) those options, like an experienced editor.

The idea is that a small model can predict "obvious" tokens well with high confidence, but tokens that need a deeper knowledge base should be handled by a bigger model.

Here's how it works:

  1. Draft Tokens: The draft model quickly predicts a short list of words (let's say 4).
  2. Evaluation: The target model evaluates these suggestions, checking if they align with its understanding. This is done by checking the ratio of the probability of the token from both the Target and Draft model
  3. Acceptance or Rejection: The final word is chosen based on rejection sampling, ensuring it matches the target model's "style."

It's like a junior writer scribbles some lines, and the editor either approves them or rewrites them to perfection. Efficient, right?

Rejection Sampling: Quality Control

Let's zoom in on rejection sampling — it's the most important point of Speculative Decoding, the bit that ensures quality.

The idea is simple: the draft model proposes a word (or token), and the target model decides if it "likes" it enough to accept. But how does it decide? Here's the formula:

$$\text{Acceptance Probability} = \min\!\left(1,\; \frac{q(x)}{p(x)}\right)$$

Here:

  • $q$ is the probability assigned by the target model to a token.
  • $p$ is the probability from the draft model to a token.

If $q/p$ is greater than 1, the target model is confident that the draft model's suggestion is solid, and accepted without question. If it's less than 1, the decision to accept is based on a coin flip weighted by this ratio.

Handling Rejected Tokens

When the target model rejects a draft token, it doesn't leave you hanging. Instead, it samples a replacement from a corrected distribution:

$$\text{Resampled Token} \sim \bigl(q(x) - p(x)\bigr)^{+}$$

A very nice mathematical proof is given for rejection sampling called "Modified Rejection Sampling recovers the target distribution" theorem in the original paper, here check it out https://arxiv.org/pdf/2302.01318

From what I understood, the target model "fills in the gap" left by the draft model's misfire. Here's why this is important:

  • If $q$ is much larger than $p$, the target model ensures the extra probability is accounted for.
  • If $p$ is overshot, the target model reins it back in.

Even if all tokens are rejected, at least one valid token is always generated in each draft-accept loop. This guarantees progress without sacrificing the overall quality of the generated text.

In addition to this, I read that an awesome extension for this approach:

Using Multiple Speculative Heads
Multi-Head Speculative Decoding extends Speculative Decoding by adding "speculative heads" to predict tokens for multiple positions (e.g., N+1, N+2, N+3) in one pass, speeding up generation. But, this approach can challenge efficiency and prediction quality, as all heads rely on a shared key-value (KV) cache, requiring alignment with the primary model for consistency.

Paged Attention and KV-Cache Optimization
Paged Attention optimizes multi-head decoding by allowing all heads to share a single KV cache. This prevents memory overload. This solution scales linearly with the number of heads.
