Memory Sparse Attention — 100M-Token Context Without RAG

Mar 28 2026 10 min read Shubham Mishra

The standard path to long-context LLMs hits a wall fast. Full attention is $O(N^2)$ — doubling context quadruples cost. The community's answer has been RAG: retrieve relevant chunks, stuff them in a 128k window, and call it a day. But RAG is a pipeline, not a model, and every joint in that pipeline is a place things can break.

Memory Sparse Attention (MSA, 2026) takes a different bet: what if the model itself learned to route queries to the right documents, attended sparsely to only those, and did it all end-to-end during pretraining? The result is a 4B-parameter model that handles 100M-token corpora and outperforms RAG stacks running 235B-parameter generators on several benchmarks.

The Core Idea

Instead of attending to all tokens in a massive context, MSA:

  1. Encodes each document offline into compressed key/value tensors ($\bar{K}$, $\bar{V}$) and a separate routing key tensor ($\bar{K}^R$).
  2. At query time, routes the incoming query against the routing keys to find the top-$k$ relevant documents via cosine similarity.
  3. Assembles a sparse context from only those $k$ documents' KVs and runs standard causal attention.

The full 100M-token corpus never fits in a forward pass. Only ~1600 tokens (16 docs × 4 compressed chunks × 25 tokens/chunk) appear in the attention matrix at any one time.

The Four Novel Components

1. Separate Router Projections

Standard transformers project hidden states $H$ into $K$ and $V$ for attention. MSA adds a third projection $W_{KR}$ that produces routing keys used only for retrieval scoring, never in the final attention computation. This lets the model develop a separate "retrieval subspace" supervised by a contrastive loss, independent of the generation subspace. 

import torch
import torch.nn.functional as F

class MSALayer(torch.nn.Module):
    def __init__(self, d_model, d_head, n_heads, chunk_size=64):
        super().__init__()
        self.W_Q  = torch.nn.Linear(d_model, n_heads * d_head, bias=False)
        self.W_K  = torch.nn.Linear(d_model, n_heads * d_head, bias=False)
        self.W_V  = torch.nn.Linear(d_model, n_heads * d_head, bias=False)
        self.W_QR = torch.nn.Linear(d_model, n_heads * d_head, bias=False)  # router Q
        self.W_KR = torch.nn.Linear(d_model, n_heads * d_head, bias=False)  # router K
        self.chunk_size = chunk_size

    def encode_doc(self, doc_hidden):
        """Offline: compress one document into its memory bank entry."""
        K  = self.W_K(doc_hidden)   # (doc_len, H*D)
        V  = self.W_V(doc_hidden)
        KR = self.W_KR(doc_hidden)
        # chunk mean-pool: (doc_len/P, H*D)
        P = self.chunk_size
        K_bar  = K.view(-1, P, K.shape[-1]).mean(1)
        V_bar  = V.view(-1, P, V.shape[-1]).mean(1)
        KR_bar = KR.view(-1, P, KR.shape[-1]).mean(1)
        return K_bar, V_bar, KR_bar

2. Document-wise RoPE

Standard RoPE assigns global position IDs $0, 1, \ldots, L-1$ across the entire context. At 100M tokens, positions far exceed any training range (typically 64k), causing catastrophic quality degradation.

MSA resets position IDs to 0 at the start of each document. Every document sees positions $0 \ldots \text{doc\_len}$ regardless of where it sits in the corpus. This enables training on 64k-token contexts while inferring over 100M-token corpora with no positional extrapolation.

3. Memory Interleave — Multi-Hop Reasoning

Some questions require chaining across documents: "what paper introduced X?" → "what did that paper's authors later build?" This is multi-hop reasoning, and most RAG systems handle it poorly because they only retrieve once.

MSA's Memory Interleave turns retrieval into a loop. The model emits document IDs as tokens, the system fetches those documents, appends them to the context, re-routes with the expanded context, and repeats until the model generates <End-of-Retrieve>.

4. Contrastive Auxiliary Loss

The router projections ($W_{QR}$, $W_{KR}$) are trained with a contrastive loss applied at every MSA layer. Given a query, positive documents (the ones that actually answer it), and negative documents:

$$\mathcal{L}_{\text{aux}} = -\frac{1}{|P|} \sum_i \log \frac{\exp(s^+_i / \tau)}{\exp(s^+_i / \tau) + \sum_j \exp(s^-_{i,j} / \tau)}$$

This is InfoNCE / NT-Xent — the same loss used in CLIP and SimCLR. The total training loss alternates between two schedules: 

def msa_loss(lm_loss, aux_loss, step, warmup_steps):
    """
    Warmup: router alignment priority
    Main:   generation priority
    """
    if step < warmup_steps:
        return 0.1 * lm_loss + aux_loss
    else:
        return lm_loss + 0.1 * aux_loss

Routing Math

For query token $t$, attention head $h$, and chunk $j$ of document $i$:

$$\text{score}(t, h, j) = \cos\!\left(\bar{Q}^R_{q,h}[t],\; \bar{K}^R_{i,j,h}\right)$$

Aggregate across heads (mean) then across query tokens (max):

$$S_{ij} = \max_t \left( \text{mean}_h\; \cos\!\left(\bar{Q}^R_{q,h}[t],\; \bar{K}^R_{i,j,h}\right) \right)$$

Document score $s_i = \max_j S_{ij}$. Select $\mathcal{I} = \text{argtopk}(\{s_i\}, k=16)$. Then assemble context:

$$K_{\text{ctx}} = \left[\bar{K}_{\text{doc}_1};\; \bar{K}_{\text{doc}_3};\; \ldots;\; K_q\right], \quad \text{Output} = \text{Attention}(Q_q, K_{\text{ctx}}, V_{\text{ctx}})$$

With $k=16$ docs, $P=64$, doc length 256: $K_{\text{ctx}}$ is 96 tokens. Standard $O(96^2)$ attention — versus $O((100\text{M})^2)$ for dense. That's a reduction of roughly $10^9\times$ in attention cost.

Complexity

Training (dominant term: intra-doc attention, linear in corpus size $L$):

$$O_{\text{train}} \approx O(L \cdot G)$$

where $G=256$ is the document length and $P=64$ is the chunk size, so $O(4L)$ — linear.

Inference (per query, amortizing offline pre-processing):

$$O_{\text{inference}} \approx O(L) \quad \text{(routing)} + O(1) \quad \text{(generation, constant in } L\text{)}$$

Tiered Storage at 100M Tokens

Getting 100M tokens to fit requires careful placement:

  • $\bar{K}^R$ (routing keys) → GPU VRAM. With chunk size 64 and d_head 128, routing keys for 100M tokens take ~56 GB — fits on 2×A800.
  • $\bar{K}$, $\bar{V}$ (content KVs) → CPU DRAM. Only the top-16 docs' content KVs get fetched to GPU per query, asynchronously.
  • Model weights → replicated on each GPU. 4B-parameter model fits comfortably; each GPU scores against its shard of $\bar{K}^R$, then a global reduce finds the top-16 indices.

Where You'd Actually Use This

A few concrete scenarios where MSA is a better fit than RAG:

  • Personal knowledge base. Index all your notes, papers, code comments, and emails into one 100M-token corpus. Query with natural language. No chunk-size tuning, no embedding model to maintain. MSA learns the retrieval metric from your actual downstream QA task.
  • Codebase-scale code understanding. Load an entire monorepo as the memory bank. Ask "where is the retry logic for the payment service?" without embedding-based semantic search, which loses precision on code. Memory Interleave handles multi-hop code navigation naturally.
  • Replace the RAG stack in production. No embedding model, no vector DB, no reranker, no thresholds. One model, one index of cached KV tensors. Update incrementally when docs change. The 4B MSA model beats RAG pipelines using 235B generators on several benchmarks.
The key conceptual shift: RAG is retrieval before the model. MSA is retrieval inside the model — the same weights that generate the answer also decide what to read.

Limitations

The offline encoding step ($O(L \cdot G)$) must re-run whenever the corpus changes — this is amortized across queries but expensive for high-churn corpora. The tiered storage architecture requires careful GPU/CPU memory management in practice. And the model must be pretrained with MSA from the start (or at least from a reasonably early checkpoint) — bolting router projections onto a fully-pretrained dense model without the contrastive warmup likely won't work well.

That said, for static or slowly-changing corpora — archives, documentation, books, codebases — the trade-off is clearly in MSA's favour. The RAG pipeline tax (three models, three latencies, three hyperparameter surfaces) is real, and MSA eliminates it in one shot.
