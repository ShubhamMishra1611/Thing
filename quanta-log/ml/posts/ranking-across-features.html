Ranking Items Across Multiple Features

Weighted sums, Borda count, Pareto dominance, TOPSIS — and when to use each.

Feb 24, 2026 · 8 min read

You have items. Each has features A, B, C. You want a ranked list. Seems simple. It's not — and the reason it's not is actually interesting.

The Setup

Here's our running dataset throughout this post. Five models, three metrics: accuracy, speed (higher = faster), and memory efficiency (higher = more efficient).

import numpy as np
import pandas as pd

data = {
    "model":      ["M1",  "M2",  "M3",  "M4",  "M5"],
    "accuracy":   [0.91,  0.85,  0.93,  0.78,  0.88],
    "speed":      [0.60,  0.95,  0.50,  0.88,  0.72],
    "memory_eff": [0.80,  0.65,  0.70,  0.90,  0.55],
}
df = pd.DataFrame(data)

We'll plug each method into this same dataset. Let's go.

Why You Can't Just "Sort"

The naive move: sort by accuracy. But M3 (best accuracy) is the slowest model. M4 (best memory) has the worst accuracy. There's no free lunch — features trade off against each other.

This is called multi-criteria decision making (MCDM), and it's been studied seriously for decades. The core tension: features are incommensurable — they're on different scales, measure different things, and may conflict. Any ranking method you pick encodes assumptions about how to resolve that conflict. The goal is to pick a method whose assumptions match your actual situation.

Method 1: Weighted Linear Combination

The simplest and most common approach. Normalize each feature, then compute a weighted sum.

from sklearn.preprocessing import MinMaxScaler

features = ["accuracy", "speed", "memory_eff"]
weights  = [0.5, 0.3, 0.2]  # must sum to 1

scaler = MinMaxScaler()
df_norm = df.copy()
df_norm[features] = scaler.fit_transform(df[features])

df_norm["score"] = df_norm[features].values @ weights
df_norm.sort_values("score", ascending=False)[["model", "score"]]

The key assumption: features are compensatory. A weakness in one feature can be offset by strength in another. If M2 is slow but very accurate, the weighted sum might still rank it highly. That's intentional — you're saying "I'll accept a slow model if it's accurate enough."

What trips people up: forgetting to normalize. If accuracy is 0–1 and speed is 0–1000 ms, the raw weighted sum is dominated by speed regardless of your weights. Always normalize first.

When to use it: you know the relative importance of features and you're okay with tradeoffs between them.

Method 2: Borda Count (Rank Aggregation)

Instead of working with raw values, rank each item per feature, then aggregate the ranks.

for f in features:
    df[f"rank_{f}"] = df[f].rank(ascending=False)

rank_cols = [f"rank_{f}" for f in features]
df["borda_score"] = df[rank_cols].sum(axis=1)
df.sort_values("borda_score")[["model"] + rank_cols + ["borda_score"]]

Lower Borda score = better (sum of rank positions).

Why this is useful: it's completely scale-invariant. You're not operating on raw values at all — only on ordinal positions. Outliers don't distort things. M3 having 0.93 accuracy vs M1's 0.91 gets treated the same as it would if M3 had 0.99 — it's rank 1 either way.

The tradeoff: you lose magnitude information. A model that's 2× faster than everything else gets the same rank-1 credit as one that's barely faster.

When to use it: features are on incomparable scales or you have outliers that would distort a weighted sum. Also great as a sanity check against Method 1 — if rankings diverge significantly, your weights are doing a lot of work.

Method 3: Pareto Dominance

This one doesn't give you a ranking. It gives you a tier. And sometimes that's the more honest answer.

Item X dominates item Y if:

  • X is at least as good as Y on all features, AND
  • X is strictly better on at least one feature

Items that no one dominates form the Pareto frontier — the set of items where you can't improve on one feature without sacrificing another.

def is_dominated(row, df, features):
    for _, other in df.iterrows():
        if all(other[f] >= row[f] for f in features) and \
           any(other[f] >  row[f] for f in features):
            return True
    return False

df["dominated"] = df.apply(lambda r: is_dominated(r, df, features), axis=1)
pareto_front = df[~df["dominated"]][["model"] + features]
print("Pareto frontier:", pareto_front["model"].tolist())

What this tells you: the Pareto frontier items are the ones worth caring about. Everything off the frontier is strictly worse than something on it — you can throw those out without any debate.

The limitation: this produces a partial order, not a total ranking. Multiple items may sit on the frontier (none dominates the others), and you'll need another method to rank within the frontier.

When to use it: as a first pass before any scoring method. It's assumption-free — no weights, no scale normalization needed. Use it to eliminate clearly inferior items, then apply Method 1 or 2 on the survivors.

Method 4: TOPSIS

TOPSIS (Technique for Order of Preference by Similarity to Ideal Solution) ranks items by their geometric distance from the ideal best point relative to the ideal worst point.

The idea: define a utopia point (max on every feature) and an anti-utopia point (min on every feature). Score each item by how close it is to utopia vs. how far from anti-utopia.

df_norm = df.copy()
df_norm[features] = scaler.fit_transform(df[features])

ideal_best  = df_norm[features].max()
ideal_worst = df_norm[features].min()

# Euclidean distance to ideal best and worst
d_best  = np.sqrt(((df_norm[features] - ideal_best)  ** 2).sum(axis=1))
d_worst = np.sqrt(((df_norm[features] - ideal_worst) ** 2).sum(axis=1))

df["topsis_score"] = d_worst / (d_best + d_worst)
df.sort_values("topsis_score", ascending=False)[["model", "topsis_score"]]

Score ranges 0–1. Higher = better. An item scoring 1.0 would be perfect on everything; 0.0 would be worst on everything.

What's different from a weighted sum: TOPSIS accounts for geometry — an item that's mediocre on everything can score worse than one that excels on one feature and is average on others, even if their weighted sums are equal.

Still needs: normalization and weights (you can weight the distance calculation if features differ in importance). Same compensatory assumption as Method 1 — tradeoffs are allowed.

When to use it: when you want a more geometrically principled single ranking and Method 1 feels too crude. Common in operations research and supplier/vendor evaluation.

Putting It Together

# Combine all rankings
results = pd.DataFrame({"model": df["model"]})
results["weighted_rank"] = df_norm["score"].rank(ascending=False).astype(int)
results["borda_rank"]    = df["borda_score"].rank(ascending=True).astype(int)
results["pareto_front"]  = (~df["dominated"]).map({True: "Yes", False: "No"})
results["topsis_rank"]   = df["topsis_score"].rank(ascending=False).astype(int)
print(results)

If all four methods agree on the top item — it's probably your best item. If they disagree substantially, that's not a flaw: it means the items are genuinely close and the ranking depends on what you value.

Which Method to Pick

Situation Use
You know feature importance Weighted linear combination
Features on incomparable scales Borda count
Want assumption-free elimination Pareto dominance first, then anything
Want geometric precision TOPSIS

One honest workflow: Pareto first to eliminate losers → Borda or TOPSIS to rank survivors → sensitivity-test by varying weights. If your top item stays top across weight variations, you're confident. If it flips, the items are genuinely close and maybe you don't need a strict ranking at all — a shortlist is the more defensible answer.

Multi-criteria ranking is fundamentally a value judgment encoded in math. Making the assumptions explicit is the whole point.
