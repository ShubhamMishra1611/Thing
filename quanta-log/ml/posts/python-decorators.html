Decorating Your Code: Python Decorators

Mar 31 2024 7 min read Shubham Mishra

Most of us who work in Python have encountered this @somename in Python code. Recently, I have used a code snippet from GitHub that uses decorator, and it is fantastic because if I were to write the code to achieve the same functionality, I would have to write a messed-up code. So, let's understand the decorator concept and make our code more elegant.

Why would I need decorators?

So, one thing about coding is that you mostly try to make code modular and explicit; decorators help achieve that pretty well. How exactly decorators help in doing so will be apparent in a while.

Before that, we just need to look into the following concepts, just to ensure we are on the same track.

  1. First Class object
  2. Python Closures

First Class object

You know, Python is a pretty versatile language; most of the "things" in Python are literally objects. And yes, functions, too, are treated as objects in Python. That means, you can use them as if they were a string or number in any programming language. Technically, functions in Python are first-class objects. You can assign it to a variable, pass it as an argument to another function, and return it from a function. In Python, they are "first-class citizen" of the language. Have a look at the following code snippet 

def doubleit(x):
  return 2 * x

f = doubleit(4)
k = doubleit

print(f'{f = } and {k = }')
# OUTPUT:
# f = 8 and k = <function doubleit at 0x7fb7910ff640>

Here, we see a clear distinction in how f holds the returned value of the function doubleit(4) while k only holds the function as an object with some address.

Now my k can actually be used as a function if I just use parentheses with it. 

k(5)
# OUTPUT:
# 10

Similarly, we can pass the function as an argument and return the function as an argument. In the following example, we pass a function as an argument to another function math_fun. 

def math_fun(func,arg_i, arg_j):
  return func(arg_i, arg_j)

def addition(i, j): return i + j

def multiplication(i, j): return i * j

print(math_fun(addition, 2, 3)) # OUTPUT: 5
print(math_fun (multiplication, 2, 3)) # OUTPUT: 6

In the following snippet, we return the function. 

def get_func(num):
  def addition(i, j):
    return i + j

  def multiplication(i, j):
    return i * j

  if num == 1:
    return addition
  if num == 2:
    return multiplication

print(get_func(1)) # OUTPUT: <function get_func.<locals>.addition at 0x7fb7910fd6c0>
print(get_func(1)(2,3)) # OUTPUT: 5

Python Closures

A Closure in Python is a function object that remembers values in enclosing scopes even if they are not in memory.

A closure — unlike a plain function — allows the function to access those captured variables through the closure's copies of their values or references, even when the function is invoked outside their scope. 

def outer_func(msg):
  def inner_func():
    print(msg)
  return inner_func

hi_func = outer_func('Hi')
bye_func = outer_func('Bye')

hi_func() # OUTPUT: Hi
bye_func() # OUTPUT: Bye

See, the function retains access to the msg variable even after outer_func has finished executing. This allows inner_func to be invoked later with the remembered value of msg. By the end of this article, you will understand how this concept fits with decorators.

Decorators

Given that we understand this property let's work to define some decorators. A straightforward example of a decorator is the following 

@staticmethod
def some_static_method(arg):
  pass

The above decorator, called staticmethod converts some_static_method some_static_method to a static method, so now this function can be accessed without creating an instance of the class.

Making custom decorators

def decorator_func(org_func):
  def wrapper():
    print(f'before the orginal function {org_func.__name__}')
    return org_func()
  return wrapper

def print_something():
  print("I am here")


@decorator_func
def print_something():
  print("I am here")

print_something()
# OUTPUT:
# before the original function print_something
# I am here

This is similar to writing

decorated_func = decorator_func(print_something)
decorated_func()
# OUTPUT:
# before the original function print_something
# I am here

So in Python, instead of writing this much, you can directly decorate a function by using @ — — — over the function, and voilà, it works.

Now, to make this decorator work with any type of function that takes any number of arguments and/or keyword arguments, we generalize the wrapper function by passing *args and **kwargs. 

def decorator_func(org_func):
  def wrapper(*args, **kwargs):
    print(f'before the original function {org_func.__name__}')
    return org_func(*args, **kwargs)
  return wrapper

@decorator_func
def print_my_name(name):
  print(f'hola {name}')

print_my_name("Shubham")

Decorators need not be only function, but they can also be class. Now let us look for more practical examples.

Writing a logging decorator

import datetime

def log(message):
    timestamp = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    print(f"[{timestamp}] {message}")

# Decorator function for logging
def log_decorator(func):
    def wrapper(*args, **kwargs):
        log(f"Calling function {func.__name__} with args: {args} and kwargs: {kwargs}")
        return func(*args, **kwargs)

    return wrapper
@log_decorator
def add(x, y):
    return x + y

# Example class with logging for methods
class Calculator:
    def __init__(self):
        pass

    @log_decorator
    def add(self, x, y):
        return x + y

    @log_decorator
    def subtract(self, x, y):
        return x - y

# Example usage
result = add(3, 5)
print("Result:", result)
# OUTPUT:
# [2024-03-31 10:18:27] Calling function add with args: (3, 5) and kwargs: {}
# Result: 8

calc = Calculator()
result = calc.add(10, 5)
print("Result:", result)
# OUTPUT:
# [2024-03-31 10:18:27] Calling function add with args: (<__main__.Calculator object at 0x7fb79105ee00>, 10, 5) and kwargs: {}
# Result: 15

result = calc.subtract(10, 5)
print("Result:", result)
# OUTPUT:
# [2024-03-31 10:18:27] Calling function subtract with args: (<__main__.Calculator object at 0x7fb79105ee00>, 10, 5) and kwargs: {}
# Result: 5

Writing a cache decorator

def cache_decorator(func):
    cache_dict = {}

    def wrapper(*args, **kwargs):
        arguments = (args, frozenset(kwargs.items()))
        if arguments in cache_dict:
            return cache_dict[arguments]
        else:
            result = func(*args, **kwargs)
            cache_dict[arguments] = result
            return result

    return wrapper

@cache_decorator
def fibonacci(n):
    if n == 1:
        return 1
    elif n <= 0:
        return 0
    return fibonacci(n - 1) + fibonacci(n - 2)

# Test the cached Fibonacci function
print(fibonacci(10))  # Output: 55

Using Multiple decorators

When you stack multiple decorators on a function, they are applied in a bottom-to-top order. This means that the decorator closest to the function definition is applied first, followed by the next decorator, and so on until the outermost decorator is applied last. 

def uppercase(func):
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        return result.upper()
    return wrapper

def add_greeting(func):
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        return "Hello, " + result
    return wrapper

@uppercase
@add_greeting
def greet(name):
    return name

print(greet("john"))  # Output: HELLO, JOHN

@add_greeting
@uppercase
def greet(name):
    return name

print(greet("john"))  # Output: Hello, JOHN

Pay attention to how, by changing the order of decorators, we are getting different outputs.

Now, let's explore decorators with arguments. While this is a powerful feature of Python decorators, it's worth noting that understanding decorators with arguments may be considered an advanced topic. We can also pass the argument on to the decorator. The following shows an example of the same: 

def log_function_calls(log_enabled):
    # This is a decorator function that takes an argument 'log_enabled'.
    # It returns another function, which is the actual decorator.
    def decorator(func):
        # This is the decorator function that takes the original function 'func' as an argument.
        # It returns yet another function, which is the wrapper function.
        def wrapper(*args, **kwargs):
            # This is the wrapper function that wraps around the original function 'func'.
            # It checks if logging is enabled based on the 'log_enabled' argument passed to the decorator.
            # If logging is enabled, it prints a message indicating the function call with its arguments.
            if log_enabled:
                print(f"Calling function: {func.__name__} with args: {args} and kwargs: {kwargs}")
            # It then calls the original function 'func' with the provided arguments and keyword arguments.
            return func(*args, **kwargs)
        # The wrapper function is returned.
        return wrapper
    # The decorator function is returned.
    return decorator

# Usage of the log_function_calls decorator with arguments.
@log_function_calls(log_enabled=True)
def add(a, b):
    return a + b

@log_function_calls(log_enabled=False)
def subtract(a, b):
    return a - b

# Example function calls to demonstrate the behavior of the decorators.
print(add(5, 3))  # Output: Calling function: add with args: (5, 3) and kwargs: {} \n 8
print(subtract(5, 3))  # Output: 2

Note: In the section discussing decorators, it's important to understand the concept of closures as they play a fundamental role in how decorators work behind the scenes. A closure in Python is a function object that retains the values of variables in the enclosing scope, even after the scope has finished executing. When we define a decorator function within another function, the inner function (the wrapper) captures and retains the variables from the outer function (the decorator), forming a closure. This allows the decorator to access and manipulate variables from its enclosing scope, enabling powerful and flexible behavior, such as modifying or augmenting the behavior of the decorated function.

We've seen how decorators can enhance code modularity, enable logging and caching functionalities, and customize behavior based on runtime conditions.
